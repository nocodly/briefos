## 1. Що є зараз (аудит коду)

Це десктоп-застосунок на **Electron 28, React і SQLite**, працює тільки під Windows. Приблизно 8 300 рядків коду.
Працює так: гаряча клавіша → FFmpeg записує звук → після зустрічі файл ріжеться на шматки по 30 с → Whisper → GPT/Claude робить підсумок.

### Критичні проблеми (через них зараз "працює погано" або небезпечно)

| # | Проблема | Де | Наслідок |
|---|----------|----|----------|
| 1 | **Ваш OpenAI-ключ вшитий в .exe** (`define process.env.OPENAI_API_KEY`) | `electron.vite.config.ts`, `build.yml` | Будь-хто розпакує `app.asar` і витягне ключ, а рахунок платитимете ви. **Ключ треба замінити негайно.** |
| 2 | **Будь-хто може сам поставити собі Pro**: клієнт пише `plan` у `profiles` напряму | `supabaseClient.ts:updateProfile`, `PlanPicker.tsx` | Безкоштовний Pro для всіх |
| 3 | Ліміт тріалу рахується локально (кількість рядків у SQLite) | `RecordingPipeline.ts:36` | Видалив зустрічі або перевстановив застосунок → ліміт знову повний |
| 4 | BYOK з порожнім ключем потихеньку переходить на ваш ключ | `RecordingPipeline.ts:142, 205` | Безлімітні зустрічі за ваш рахунок |
| 5 | Для звуку системи потрібен VB-Cable або Stereo Mix (dshow) | `AudioCapture.ts` | Головна причина, чому "не працює" у звичайних користувачів |
| 6 | Розпізнавання мовців через Python + pyannote + HF-токен | `Diarizer.ts`, `python/` | У 99% користувачів Python немає, тож функція мертва |
| 7 | Транскрипція стартує тільки ПІСЛЯ зустрічі | `RecordingPipeline.process` | Після годинного дзвінка підсумок доводиться чекати кілька хвилин |
| 8 | Stripe webhook не обробляє скасування й продовження підписки | `stripe-webhook/index.ts` | Хто скасував підписку, лишається на Pro назавжди |
| 9 | Ключ шифрування налаштувань захардкоджений | `store.ts:67` | Збережені ключі користувачів фактично не захищені |
| 10 | Немає сайту (лендингу) для реклами | — | Рекламу нікуди вести |

**Висновок:** перші шари (UI-компоненти, SQLite, промпти, експорти) можна переносити.
**Ядро потрібно переробити:** запис звуку, обробку AI і білінг. Оновлювати його латками немає сенсу.

## 2. Що робить Granola (на що орієнтуємось)

- **Без бота:** пише звук з компʼютера, у дзвінок нічого не підключається
- **Блокнот:** людина під час зустрічі пише короткі нотатки, а AI потім **доповнює їх транскриптом**. Це головна фішка: нотатки свої, а не "робот написав"
- Шаблони нотаток (1:1, sales, standup, співбесіда)
- Чат з усіма зустрічами ("що ми вирішили з клієнтом X?")
- Календар: нагадує про зустріч, підтягує учасників, робить коротку довідку перед зустріччю
- Follow-up email, action items
- Інтеграції: Slack, Notion, HubSpot, Zapier, MCP (Claude/ChatGPT)
- Платформи: Mac, Windows, iOS, Android
- **Тарифи:** Free — безлімітні нотатки, але історія лише 30 днів, AI-чат тільки в режимі Auto, зі звʼязків тільки Slack · Business — $14/люд/міс · Enterprise — $35/люд/міс

**Чим відрізняємось ми:**
1. **Звіти за період** (тиждень/місяць/квартал по всіх зустрічах). У BriefOS це вже є, Granola такого не має
2. Сильна мультимовність: українська, російська, німецька, польська (а не тільки EN)
3. Ціна нижча: $10–12 проти $14

## 5. Нова архітектура

```
┌──────────────── Десктоп (Electron, Win + Mac) ────────────────┐
│ Renderer (React)                                              │
│  • getUserMedia → мікрофон  ──┐                               │
│  • getDisplayMedia(loopback)  ├─► 2 канали: "Я" / "Вони"      │
│    → звук системи (без VB-Cable) ┘   MediaRecorder (opus)     │
│  • кожні ~15 с шлемо шматок на сервер ──────────────┐         │
│  • блокнот (TipTap), живий транскрипт, AI-нотатки   │         │
│ Main: tray, гаряча клавіша, автодетект дзвінка, SQLite│         │
└──────────────────────────────────────────────────────┼─────────┘
                                                       ▼
┌──────────────────── Сервер (наш, ключі тільки тут) ───────────┐
│ API (Supabase Edge Functions або Node на Railway)             │
│  /transcribe-chunk  → OpenAI transcribe → текст назад         │
│  /enhance-notes     → LLM: нотатки + транскрипт → результат   │
│  /chat, /period-report, /follow-up                            │
│  Перевірка JWT + квоти + плану ПЕРЕД кожним AI-викликом       │
│  Аудіо НЕ зберігаємо (видаляємо після транскрипції)           │
├───────────────────────────────────────────────────────────────┤
│ Supabase Postgres: profiles, usage, subscriptions, meetings*  │
│  RLS: користувач НЕ може змінювати plan/usage                 │
│ Stripe: Checkout + Customer Portal + webhook (повний цикл)    │
└───────────────────────────────────────────────────────────────┘
┌──── Сайт (Next.js на Vercel) ─────────────────────────────────┐
│ Лендинг, ціни, download, privacy, terms, блог/SEO, аналітика  │
└───────────────────────────────────────────────────────────────┘
* meetings у хмарі потрібні для синхронізації/чату/шерінгу; локально лишається кеш у SQLite
```

### Ключові рішення
1. **Звук без драйверів:** `session.setDisplayMediaRequestHandler(... audio: 'loopback')` в Electron. На Windows працює з коробки, на macOS 14.2+ теж. Для цього **треба оновити Electron 28 → актуальну версію**.
2. **Два канали замість pyannote:** мікрофон — це "Я", системний звук — "Співрозмовники". Так робить і Granola. Python і HF-токен видаляємо.
3. **Транскрипція під час зустрічі:** шматки по 15–30 с вантажимо одразу, тож AI-нотатки готові через 5–10 с після кінця дзвінка.
4. **Всі AI-ключі тільки на сервері.** Клієнт отримує тільки Supabase JWT.
5. **Квота на сервері:** таблиця `usage(user_id, month, meetings, minutes)` + атомарна перевірка в `/transcribe-chunk`.
6. **План міняє тільки Stripe webhook** (service role): `checkout.session.completed`, `customer.subscription.updated/deleted`, `invoice.payment_failed`. Зберігаємо `stripe_customer_id`.
7. **Що видалити:** FFmpeg-запис, ChunkManager, Diarizer/python, BYOK-екрани, HF-токен, SMTP-налаштування (email шлемо з сервера через Resend), puppeteer (PDF робимо через `webContents.printToPDF`, мінус ~150 МБ у збірці).

### Структура репозиторію (монорепо)
```
minutama/
  apps/
    desktop/        ← Electron (переносимо з briefos/src)
      src/main/       tray, hotkey, meeting-detect, ipc, updater, db
      src/renderer/   pages/ (Home, Meeting, Chat, Reports, Settings)
                      components/ (Notepad, Transcript, TemplatePicker…)
                      audio/ (recorder.ts — mic+loopback, uploader.ts)
    web/            ← Next.js лендинг + /pricing /download /privacy /terms
  supabase/
    migrations/     ← profiles, usage, subscriptions, meetings, RLS
    functions/      ← transcribe-chunk, enhance-notes, chat,
                      period-report, follow-up, stripe-webhook, billing-portal
  packages/
    shared/         ← типи, плани/ліміти (одне джерело правди), промпти
```

- [ ] Перевірити, чи публічний репозиторій `nocodly/briefos` і GitHub Releases

- [ ] Міграції: `profiles`, `usage`, `subscriptions`, `meetings`, `notes`, `transcript_segments`

- [ ] Спільний файл `plans.ts` з лімітами (використовують і сервер, і клієнт)

### Етап 2 — Ядро десктопа (5–7 днів)
- [ ] Оновити Electron, монорепо, ребрендинг
- [ ] Новий рекордер: мікрофон + loopback, 2 канали, завантаження шматків, офлайн-черга
- [ ] Живий транскрипт під час дзвінка

### Етап 3 — Pro-функції (4–5 днів)

### Етап 4 — Новий дизайн (паралельно з етапами 2–3, 3–4 дні)
- [ ] Дизайн-система: нова палітра, шрифти, логотип (стиль Granola — чисто, світло, "паперовий" блокнот, але своє)

- [ ] Онбординг на 3 кроки: вхід Google → дозвіл на мікрофон → тестовий запис. **Без вибору тарифу й ключів на старті**
- [ ] Віджет-оверлей під час запису

### Етап 5 — Сайт і запуск (3–4 дні)
- [ ] Лендинг: hero + відео-демо, "без бота", як це працює (до/під час/після), звіти за період, мови, ціни, FAQ, download

- [ ] Аналітика (PostHog): реєстрація → перший запис → 3-й запис → оплата
- [ ] Sentry для помилок
- [ ] Бета на 10–20 людей перед платною рекламою

### Етап 6 — Після запуску
- macOS-збірка, Team-тариф, HubSpot/Zapier, MCP-конектор, мобільний застосунок
